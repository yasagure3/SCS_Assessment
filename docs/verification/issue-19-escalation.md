# AI下書き: 採用結果不明時の再送に関する残存指摘

匿名化済み入力の確認、生成・状態照会、下書きへの採用、人による確定は実装済み。修正後の全体試験はFront105、Workers158、bootstrap3、Edge22成功。独立した再レビューで、採用応答喪失後の復旧に未解消の問題を再現した。

## 再現結果

サーバーで採用が成功しても応答が失われると、画面は診断を再取得する。再取得でrevisionが進むと、再試行時のbodyと操作IDが変わり、同じ操作の確認ではなく新しい採用になる。その間に根拠も変わるとボタンが無効となり、保存済みの成功結果を再確認できない。

実際の画面部品と送信処理に対する独立試験では、版が変わらない対照は成功、採用による版更新と採用後の根拠変更の2条件は失敗した。サーバーの保存済み結果再送は独立試験30件で成功しており、残る修正対象は画面の復旧経路である。

## 追加修正案

採用開始時の入力と操作IDを結果が確定するまで保持する。結果不明の再確認と新規採用を画面で区別し、診断の版や根拠が変わっても同じ入力とIDで保存済み結果を確認できるようにする。現在の閲覧・更新権限は引き続きサーバーで検査し、根拠の古い新規採用を許可しない。

版不変・採用による版更新・採用後の根拠変更の3条件を回帰検証し、全体試験と独立レビューを行う。実AIへの送信や本番公開は含まない。

## 判断が必要な理由

dev-implのレビュー2回・high修正1回の後にhigh/spec-complianceが画面側へ転移して残ったため、追加修正サイクルの判断を求める。判断まではブランチを保存し、mainへ統合しない。
