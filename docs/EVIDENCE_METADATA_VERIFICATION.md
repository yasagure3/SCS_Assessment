# 証跡の参照情報・基準別確認（Issue 16）

ファイル本文のアップロード・取得は Issue 17 の範囲。今回の縦動線は、顧客・案件 → 診断 → 証跡 → 文書名/URL/箇所と1〜81基準を登録 → 基準ごとの確認 → 基準詳細で自己評価・取込原文と照合 → 編集/関連解除。

APIの省略可能な登録項目は、url/fileIdをnull、locationを空文字に正規化する。編集APIは文書名・URL・箇所・関連基準の置換で、fileIdの差替えを受理しない。基準関連の順序は意味を持たない集合として扱う。関連基準も助言のbasisHashと確認対象hashに含めるため、基準追加/解除時は保持された基準にも再確認が作用する。

証跡・Review・課題の解除は診断の1行CASと共通receipt/履歴/監査の同一batchで保存する。自己評価、編集回答、取込原文、過去の確定助言内容は維持する。助言のbasisHashは変わり、旧確定助言は再確認対象になる。課題の完了確認を解除し、done/awaiting_reviewをdoingへ戻す。todo/doingは維持する。確認変更はその基準を参照する課題だけに作用する。

受理済みの操作は、現在のアクセス権を再確認してから台帳の保存結果を返す。後続操作で証跡が削除されていても、元の成功結果を再送できる。戻り値は保存したrevisionの診断DTOと同じ版の集計で、更新後の別GETに成功表示を依存させない。

## シナリオと検証の対応

| 重要度 | シナリオ | 検証 |
|---|---|---|
| Critical | 自己評価と原O〜Rが証跡操作で変更されない | Workers / E2E |
| Critical | 別顧客、別案件のファイル、未ready、無関係基準を拒否 | Workers |
| Critical | 編集・確認・関連解除で助言と参照課題を同時に再確認へ戻す | Workers（done/awaiting_review/todo/doing） |
| Critical | CAS競合・途中失敗・冪等再送で部分保存/二重保存がない | Workers（実D1と失敗trigger） |
| Major | 基準別確認、note必須、確認者・時刻・hashのサーバー設定 | Workers / Front / E2E |
| Major | 必須・不正URL・未知field・重複/未知基準・Unicode文字数・100件/1MiB | Workers / Front |
| Major | 初期読込/失敗/再試行、保存中抑止、失敗時入力保持、409差分 | Front / E2E |
| Major | 権限失効時にキャッシュを隠す、保管後は編集無効 | Front（共有画面境界も含む） |
| Major | URLの自動fetchなし、明示リンクにnoopener/noreferrer | Workers（fetch監視） / Front / E2E（要求監視） |
| Major | ナビと基準詳細の接続、通常幅・狭幅の配置 | E2E / 生成画像の目視 |

新規APIは未実装の404からREDを確認し、Frontは未実装モジュールで失敗を確認して実装した。省略項目の受理は422のREDから追加した。既存共有保存機構の競合/原子性・権限境界の追加ケースはcharacterizationとして補完している。テストは状態変化、保持する値、保存結果を検査し、不在assertだけで合格にしない。
