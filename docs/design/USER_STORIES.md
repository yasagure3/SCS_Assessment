# SCS診断・助言サービス ユーザーストーリー

更新日: 2026-09-18
状態: 初稿レビュー済み。UIスケッチは2026-09-18にユーザー確認済み。Q13により未回答/証跡未確認を明記して出力可能。Q14により保存先は設計案を見て決定。未決事項は要件ヒアリング文書を参照。

## 対象と利用者

初回は★3に限定する。複数顧客を支援する当社担当者が利用し、顧客にはPDF・Excelのレポートを渡す。

| 利用者 | 主な目的 |
|---|---|
| 診断担当者 | Excelを取り込み、現状・根拠・課題を整理する |
| 助言の確認担当者 | 定型助言とAI案を確認・編集し、顧客に渡す内容を確定する。同じ担当者が兼任可能 |
| 運用管理者（役割分担は設計案） | 社内利用者と案件のアクセス、利用設定を管理する |
| 顧客の経営層・実務担当者 | レポートを受け取り、意思決定・対策実施に使う。初回はログイン利用者に含めない |

## Must

### US-001 顧客を登録・検索・更新する

- As a 診断担当者
- I want to 顧客の基本情報と診断案件を一覧・検索・更新したい
- So that 複数顧客の支援状況を取り違えずに把握できる
- Given 複数顧客が登録済み When 顧客名を検索する Then 一致する顧客とその診断案件を表示する。
- Given 顧客詳細を開いている When 基本情報を更新する Then 他の顧客のデータは変わらない。

### US-002 ★3診断案件を作成する

- As a 診断担当者
- I want to 顧客ごとに診断案件と評価対象を登録したい
- So that どの範囲・時点・制度版を診断したか説明できる
- Given 顧客を選択済み When 案件を作成する Then 目標★3、案件名、診断時点、参照制度版を保持する。
- Given 診断の対象範囲が未記入 When レポート確定を試みる Then 対象範囲の記入を求める。
- Q07決定: 対象会社・拠点・部署・システムを案件内で明記する。

### US-003 Excelの取込内容を確認する

- As a 診断担当者
- I want to Excelのシート・評価基準・回答の対応を確認して取り込みたい
- So that 列の誤認や欠損を診断前に発見できる
- Given 添付書式のExcel When プレビューを開く Then L列を評価基準No.、O〜R列を回答とし、結合セルの要件情報を復元する。
- Given 未知の評価基準No.・重複No.・未対応の自己評価記号がある When 検査する Then 該当行を示し、未解決のまま確定しない。
- Given 制度版の★3基準一覧に対して行が欠落している When 検査する Then 欠落No.を表示し、黙って集計分母から除外しない。取込の扱いはプレビューで明示する。
- Given ★3・★4が同居するExcel When ★3案件に取り込む Then ★4追加基準を★3の集計分母に含めない。

### US-004 現状を集計する

- As a 診断担当者
- I want to 大分類別・評価基準別の現状を見たい
- So that 対応すべき領域を説明できる
- Given 提供された一次スクリーニングExcel When 初回集計する Then ★3基準81件、○24件、△24件、✖28件、未回答5件になる。
- Given いずれかの自己評価を更新した When 集計を見る Then 該当する件数だけが変わり、合計と分類別内訳が一致する。
- 自己評価○の割合は公式の取得判定や取得確率として表示しない。

### US-005 判定・理由・対応案を確認・編集する

- As a 診断担当者
- I want to 評価基準とO〜R列の原文を並べ、確認した内容を編集したい
- So that 一次回答の意味を失わずに診断を具体化できる
- Given 取込済み When 詳細を開く Then 公式評価基準、元回答、現在の判定理由、既存の根拠、今後の作業を区別して表示する。
- Given 編集する When 保存する Then 元ファイルの値と編集後の値を区別して保持する。
- Given 未回答・対象外の可能性・△ When 確認する Then 自動的に○や半点へ変換しない。

### US-006 証跡の参照情報を管理する

- As a 診断担当者
- I want to 根拠文書の名称・URL・該当箇所・確認状況を評価基準に関連付けたい
- So that 判定を説明するための根拠を辿れる
- Given 評価基準詳細 When 証跡情報を登録する Then 文書名、参照先、該当箇所、確認状態が保存される。
- Given 証跡が添付されただけ When 集計する Then 内容確認済みや適合確認済みには自動変更しない。

### US-007 証跡ファイルを添付する

- As a 診断担当者
- I want to 必要な根拠ファイルを評価基準から閲覧したい
- So that 規程や記録を探す手間を減らせる
- Given 権限のある案件 When 対応するファイルを添付する Then 当該案件・評価基準に関連付けて表示する。
- Given 閲覧権限がない案件 When ファイルの取得を試みる Then 内容を返さない。
- Given ファイルを保管した When AI機能を開く Then 保管だけを理由にAIサービスへ送信しない。
- ファイル種類・サイズ上限は実現可能性検証で確定する。

### US-008 定型助言を表示・編集する

- As a 診断担当者
- I want to 不足項目に対する具体的な作業と必要な証跡例を確認したい
- So that 顧客に着手可能な対策を説明できる
- Given 未達・要確認の基準 When 助言を開く Then 不足点、実施手順、証跡例、完了確認方法、対応する基準を表示する。
- Given 顧客別に編集した When 保存する Then 元の定型助言と編集後の助言を区別する。
- 公式要求と実装例・推奨事項を区別する。

### US-009 AIによる個別助言案を作成する

- As a 診断担当者
- I want to 顧客の状況に応じた助言の下書きを作りたい
- So that 定型助言を具体的な対策へ展開できる
- Given AI利用可能な案件 When 担当者が匿名化済みの回答・不足点と要件を確認して生成する Then その確認済み入力のみを使い、下書きとして表示する。証跡ファイル本文は送信しない。
- Given AI生成が失敗する When 助言画面を使う Then 既存の定型助言と手動編集を継続でき、回答・証跡は失われない。
- Q08により送信範囲は確定。事業者・モデル・契約は未選定。

### US-010 助言を確認・確定する

- As a 助言の確認担当者
- I want to AI案と定型案を検討し、顧客向け助言を確定したい
- So that 誤解釈や顧客事情に合わない対策を修正できる
- Given 下書きの助言 When 確認・編集して確定する Then 確定内容、確認者、確認日時、参照版を残す。
- Given 未確認のAI案 When 顧客提出用レポートを出力する Then その案をPDF・Excelに含めず、未確認の案があることを出力前に担当者へ示す。

### US-011 改善課題を管理する

- As a 診断担当者
- I want to 課題に担当者・期限・進捗を設定したい
- So that 対策の滞留や未着手を把握できる
- Given 課題がある When 担当者・期限・進捗を更新する Then 課題一覧と詳細に反映する。
- Given 期限を過ぎた未完了課題 When 一覧を表示する Then 期限超過として識別できる。
- 担当者の登録だけで顧客にアカウントや通知を自動発行しない。

### US-012 改善の完了を確認する

- As a 助言の確認担当者
- I want to 改善作業の結果と証跡を確認したい
- So that 作業完了と要件の充足を区別できる
- Given 担当者が作業を完了報告した When 確認する Then 関連証跡と完了条件を確認し、確認結果を記録できる。
- Given 作業だけを完了にした When 診断結果を見る Then 評価基準の判定を自動で○へ変更しない。

### US-013 再診断を比較する

- As a 診断担当者
- I want to 前回と今回の判定・課題を比較したい
- So that 改善と残課題を顧客に説明できる
- Given 前回診断がある When 再診断する Then 前回を保持したまま新たな診断時点を作る。
- Given 同じ評価基準No. When 比較する Then 前回と今回の状態の変更（例: ✖→△）・変更なし・未回答を区別する。△を必ず部分的改善とみなす順序付けはしない。
- Given 制度版や対象範囲が異なる When 比較する Then 単純比較できない理由と変更箇所を表示する。

### US-014 レポートを確認する

- As a 診断担当者
- I want to 経営層向けサマリーと詳細対策を確認したい
- So that 顧客の意思決定と実務の両方に使える報告書を作れる
- Given 診断案件 When プレビューする Then 対象範囲、診断日、制度版、状態別件数、主要課題、項目別判定・対策を表示する。
- Given 根拠未確認の○や未回答がある When 出力する Then 確認状況が失われず、制度上の取得済みと誤認する表現を使わない。

### US-015 PDFでレポートを出力する

- As a 診断担当者
- I want to 顧客に配布できるPDFを保存したい
- So that 経営層と実務担当者が同じ診断結果を参照できる
- Given レポートを確認済み When PDF出力する Then サマリーと詳細が同一診断時点の内容で出力される。
- Given 長い日本語の対策文 When 出力する Then 改ページで本文・表が欠落せず、読みやすく表示される。

### US-016 作業用Excelを出力する

- As a 診断担当者
- I want to 判定・根拠・対策・担当・期限・進捗をExcelへ出力したい
- So that 顧客が改善作業に使える
- Given 案件を選択済み When Excelを出力する Then 評価基準No.で追跡可能な表と集計を保存する。
- Given PDFとExcelを同じ診断時点から出力する When 件数を比較する Then 状態別・分類別の件数が一致する。
- Given 数式のように見える自由記述 When 出力する Then 文字列として保存し、不意に計算・リンク実行されない。

### US-017 社内利用者としてアクセスする

- As a 当社担当者
- I want to 自分に許可された診断案件を安全に利用したい
- So that 顧客の回答や証跡を適切に管理できる
- Given 未認証または権限なし When 案件や証跡を取得する Then 内容を返さない。
- Given 権限のある利用者 When 案件を開く Then 必要な操作だけを表示・許可する。
- Q09決定: 招待制のメールアドレス＋パスワード＋多要素認証。Q11は進行指示を受け「管理者は全顧客、担当者は割当顧客のみ」をスケッチの仮定とする。
- Given 招待されていない利用者 When アカウント作成を試みる Then 顧客データを扱える利用者として登録されない。
- Given 有効な招待を受けた利用者 When 登録を進める Then パスワードとMFAを設定できる。
- Given パスワード確認済みでMFAが未完了 When 案件・証跡・レポートにアクセスする Then 内容を返さず、MFA完了を求める。

## Should（追加候補・未確定）

### US-018 再取込の差分を確認する

- As a 診断担当者
- I want to 更新Excelと現在の入力の差分を確認したい
- So that サイト側の修正を誤って上書きしない
- Given 既に回答を編集済み When 同じ案件に再取込する Then 評価基準No.に基づく変更・衝突を表示する。
- Given 取込を取り消す When 案件を表示する Then 現在の回答は変更されていない。

### US-019 制度版の変更を把握する

- As a 診断担当者
- I want to 新旧の評価基準の変更を把握したい
- So that 過去の助言を無条件に使い回さずに済む
- Given 制度版を追加した When 過去診断を見る Then 過去の結果と参照版は維持される。
- Given 基準内容が変わった When 新しい診断に引き継ぐ Then 再確認対象として表示する。

### US-020 編集・確認の履歴を追跡する

- As a 助言の確認担当者
- I want to 判定・助言・証跡確認の変更履歴を確認したい
- So that 誰が何を根拠に報告内容を変更したか説明できる
- Given 診断内容が変更された When 履歴を開く Then 変更者、日時、対象項目、変更前後を確認できる。
- Given 別案件にアクセスする権限がない When 履歴を取得する Then 他案件の情報を返さない。

## Won't（初回の対象外）

- ★4診断・助言・レポート（次段階で対応）。
- 顧客向けログインと共同編集。
- SCS制度上の登録申請の代行・自動送信、認定・取得の自動判定。
- AIの未確認案を顧客へ自動送信する機能。
- 課金・オンライン決済。

## 未決事項と設計上の前提

- Q10の白基調の業務画面はユーザー確認済み。Q11は管理者全件・担当者は割当顧客のみという設計前提。Q12の運用条件は未定。
- ○・△・✖・未回答は原文の意味を保持する。対象外は初回に独立状態を追加せず、証跡確認・自己評価は独立。USECASES.mdとDESIGN.mdに詳細を定義した。
- クラウド保存の条件、保持・削除期間、利用規模、期限は未確定。本番利用前に判断する。
- Excel・日本語PDF・更新/権限境界の局所PoCを検証済み。実クラウド/MFA/AI接続と本番規模の測定は未実施。FEASIBILITY.md参照。
- この初稿の優先度は、ユーザーが明示した初回機能をMust、運用改善をShouldとして整理した案。
