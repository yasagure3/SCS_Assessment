# SCS診断・助言サービス 要件ヒアリング

更新日: 2026-09-18
状態: 要件1〜9、13〜14確定。2026-09-18にユーザーがブラウザでUIスケッチを確認し「進めてください」と指示。ユースケース・技術検証・詳細設計へ進行。製造フェーズは未着手。

## ユーザーから指定された事項

- SCS評価制度の★3・★4取得に向けた、課題の可視化・診断・助言サービスを作る。
- Excel取込、集計による現状把握、レポート作成、要件を満たすための具体的な改善助言を提供する。
- 提供ExcelのO〜R列が一次スクリーニング結果。
- `skanehira/fullstack-worker-template` を使用する。
- 参考の `UI_SKETCH.html` と同様のUIスケッチを作成してから製造へ進む。
- システムの特性を踏まえ、設問形式で一般的な要件を整理する。
- 追加提供された `dev-spec.skill` を設計の参考にする。使用中のスキルと全13ファイルの本文が一致することを確認済み（改行形式を正規化して比較）。

## 確定した回答

| ID | 論点 | 決定 |
|---|---|---|
| Q01 | 利用者・運用形態 | 当社担当者が複数顧客を管理し、顧客にはレポートを渡す |
| Q02 | 初回の★3・★4対応範囲 | 初回は★3に限定。★4は次の段階で追加する |
| Q03 | 助言の作成方式 | 定型助言＋担当者編集とAI個別案＋担当者確認を組み合わせる |
| Q04 | レポートの内容と形式 | 経営層向けサマリー＋項目別課題・対策をPDFで出力し、作業用Excelも出力する |
| Q05 | 証跡管理 | 文書名・URL・該当箇所・確認状況を管理し、必要なファイルも添付する |
| Q06 | 改善作業の追跡 | 課題ごとに担当者・期限・進捗・完了確認を管理し、再診断で前回との差分を表示する |
| Q07 | 診断範囲 | 顧客ごとに診断案件を作り、対象会社・拠点・部署・システムを案件内で明記する |
| Q08 | AIに送る情報 | 要件と担当者が確認した匿名化済みの回答・不足点のみ。証跡本文は送信しない |
| Q09 | ログイン | 招待制のメールアドレス＋パスワード＋多要素認証 |
| Q13 | 未回答/証跡未確認時のレポート | 出力可能。未回答・未確認の件数と内容を明記する |
| Q14 | 保存先・運用条件 | 現時点で保存先指定なし。設計案を見て決める。利用規模・時期は回答なし |

Q14は保存先の承認ではない。Cloudflare/AWS等への本番接続・実データ保管を確定したとは扱わない。Q10の画面外観はスケッチ確認で採用、Q11の権限案は引き続き設計上の前提とし明示する。

Q03は「1と2のミックス」との回答。公式要件に紐づく定型助言を土台とし、AIが顧客別の案を補助し、担当者が編集・確定する。Q08により、匿名化済みの回答・不足点を担当者が確認したうえで送信する。証跡本文は送信しない。AI事業者・契約は未選定。

## 仮置きと未確定事項

| ID | 論点 | 選択肢 | 推奨案 |
|---|---|---|---|
| Q10 | UIの見た目 | 白基調・紺と青の業務画面／参考に近い暗い背景／ブランド指定 | 白基調の業務画面 |

ユーザーの進行指示を受け、Q10は白基調・紺と青、Q11は管理者全件＋担当者は割当顧客のみをスケッチの仮定として採用する。本人がその選択肢を選んだという記録にはしない。Q12は未定のまま保持し、クラウド保存・外部サービス契約・本番公開はこの仮定で進めない。

## 次の設問候補

回答に応じて3問程度ずつ提示し、既に確定した事項は再質問しない。

1. ○・△・✖・未回答の意味と扱い。対象外の根拠・確認者を残すか。
2. Excelの対応書式、再取込時の差分確認と編集内容の扱い。
3. 助言に含める内容（手順・証跡例・完了条件・優先度・工数・費用等）。
4. 保持・削除期間。Q12の条件に応じた追加確認。

## スケッチで確認する主要な流れ（案）

顧客一覧 → 診断案件・適用範囲 → Excel取込・列対応確認 → 現状ダッシュボード → 評価基準詳細・根拠確認 → 改善助言・対策計画 → レポート確認・出力。

初回の画面は★3に限定する。証跡管理、PDF・Excelレポート、改善追跡・再診断を含める。AIには確認済み匿名化回答・不足点のみを渡す。★4の拡張余地はデータモデルに残すが、初回機能には追加しない。

## 設計の進め方

5. 設計内容を具体的にレビューできる状態にして製造へ進む。
